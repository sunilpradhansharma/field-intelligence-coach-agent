# Quickstart & Validation: Morning Coaching Brief (MVP)

A run/validation guide that proves the feature works end-to-end. Implementation details
live in `tasks.md` (generated by `/speckit.tasks`) and the code itself.

## Prerequisites

- Python 3.11+
- AWS credentials with Amazon Bedrock access (Claude + Titan embeddings) in a region where
  the AbbVie-approved Claude model is enabled.
- Environment configuration (no hard-coded model id):
  - `BEDROCK_MODEL_ID` — the approved Claude model id
  - `AWS_REGION` — Bedrock region
  - `BEDROCK_EMBED_MODEL_ID` — Titan embeddings model id
  - `COACH_DB_PATH` — local SQLite/DuckDB path (default `./data/coach.db`)
  - `COACH_SEED` — integer seed for repeatable synthetic data (default `42`)

## Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .              # installs src/coach + deps (FastAPI, langgraph, boto3, faiss/chroma, duckdb/sqlite, pytest)

# Generate seeded synthetic data (1 region, 2 districts, 8–12 reps each) + build the notes index
python -m coach.synthetic.generate --seed "$COACH_SEED"
```

## Run

```bash
uvicorn coach.api.app:app --reload      # FastAPI backend
# open web/index.html (or the served root) in a browser
```

## End-to-end validation scenarios

> See [contracts/api.md](./contracts/api.md) for exact request/response shapes and
> [data-model.md](./data-model.md) for object fields.

### Scenario A — DM morning brief (happy path, P1–P5)
1. Call as DM of District 1 (`X-User-Id: dm_d1`): `GET /api/reps?limit=5`.
2. **Expect**: a ranked list of D1 reps; every rep has a visible `reason` with signals +
   weights + data points. (Validates US1, FR-002/003/010.)
3. Pick the top rep: `GET /api/brief/{rep_id}`.
4. **Expect**: all five sections present — 1–3 coaching focus areas (each with a reason),
   ride-along prep (last notes, agreed actions, observe-next), key accounts with business
   context and at least one mismatch flag where warranted, and a suggested opener — each
   carrying a reason. (Validates US2–US5, FR-004…009.)

### Scenario B — RBAC enforcement (Principle V)
1. As DM of District 1, request a District 2 rep: `GET /api/brief/{d2_rep_id}`.
2. **Expect**: `403`; no D2 data in the response body.
3. As the RBD (`X-User-Id: rbd_r1`): `GET /api/reps` returns reps from **both** D1 and D2
   (region read-only); attempting any write/action is rejected.
4. **Expect**: zero out-of-scope rows in any DM response (SC-003).

### Scenario C — Empty / sparse states (FR-018)
1. Request the brief for a seeded rep with **no** coaching history.
2. **Expect**: ride-along prep returns an explicit "no prior history yet" empty state, not
   blank fields; sparse account data is reported as missing, not fabricated.

### Scenario D — Determinism / example-based golden check (IX, SC-006)
1. With `COACH_SEED=42`, run the ranking for District 1.
2. **Expect**: ranked rep ids, scores, and reason objects match the committed golden
   fixture exactly (the deterministic scorer guarantees repeatability).

## Automated tests

```bash
pytest tests/unit         # scorer + fixed weights, RBAC filter (2-district seed), reason schema, guardrail hook
pytest tests/component    # each of the 5 components against seeded data
pytest tests/e2e          # full brief + rubric (all 5 sections present AND each has a reason) + golden ranking
pytest                    # all levels
```

### Rubric gate (encodes the fixed checklist)
The e2e rubric test asserts a brief is **complete** only if:
- [ ] Section 1 ranked reps present, each with a reason
- [ ] Section 2 has 1–3 focus areas, each with a reason
- [ ] Section 3 ride-along prep present (or explicit empty state)
- [ ] Section 4 key accounts with business context + mismatch flagging, each with a reason
- [ ] Section 5 opener present with a reason
- [ ] No recommendation anywhere lacks a visible reason (FR-010)

## Success-criteria mapping

| Criterion | Validated by |
|-----------|--------------|
| SC-001 (brief in <5 min) | Scenario A timing |
| SC-002 (100% reasons shown) | Rubric gate + reason-schema unit tests |
| SC-003 (100% in-territory) | Scenario B + RBAC unit tests |
| SC-004/005 (consistency/completeness) | Rubric scoring across two DM runs |
| SC-006 (example-based checks pass) | Scenario D golden fixtures |
| SC-007 (synthetic only) | `synthetic:true` assertion; no real connectors configured |
